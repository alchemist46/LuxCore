# LuxCore roadmap: the open work

Consolidated 2026-10-21 (HEAD `158a5b409`) from the unfinished items of [MODERNIZATION_PLAN.md](docs/history/MODERNIZATION_PLAN.md) and the whole of [SPEEDUP_CHANGES.md](docs/history/SPEEDUP_CHANGES.md). It lists open work only. The done items, their measurements and the reasoning behind them stay in those two files and in [MODERNIZATION_RESEARCH.md](docs/history/MODERNIZATION_RESEARCH.md) (papers, engine comparisons), all in `docs/history/`; each entry below says where to look (*History*). Bugs are in [BUGS.md](BUGS.md); an item that fixes one names it. Bugs with no item here are standalone fixes.

## 1. Where the engine stands

Against Cycles on the same RX 6950 XT (G0 re-measure of 2026-10-17, light tree build): **4.5x** at equal error on the Blender Cornell box, **8.6x** on the Blender classroom. The two factors, from the speedup plan:

| | Cornell box | classroom |
|---|---|---|
| time per sample, PATHOCL / Cycles | ~1.4x | ~3x |
| variance per sample, PATHOCL / Cycles | ~1.8x | ~0.85x |

The trace is not the limit (203M rays/s on the 32-triangle Cornell box, 187M on the 247k-triangle classroom). Textured scenes lose on the shading of a vertex; simple scenes lose on direct-light noise. The fixed cost of a render is 0.85-4.3 s against 0-0.3 s for Cycles. The cold kernel compile is solved on Windows (G9).

Done, for orientation: CI with tests and the benchmark set; S0 (the kernel timing and the textures' share); A3; B3 (the learning stop); B4; E3; the texture half of G11b; Owen-scrambled Sobol with blue-noise pixel decorrelation; the per-pixel adaptive halt (as an option); GGX/VNDF and energy compensation always on; the material standards pass; random-walk subsurface; OpenPBR; the Arnold/Cycles path depths; the working colour space; the light tree as the default strategy; G1-G5, G7, G10, G11; G9 on Windows; C1-C5; F1-F3; P1-P3; RANDOM sampler removed.

## 2. Conventions

Measurement rules (from [CLAUDE.md](CLAUDE.md) and the speedup plan):
- GPU (PATHOCL on HIP) by default; CPU engines only when a test needs them. Short runs first.
- Noise without a reference: two seeds, `mean((a-b)^2)/2`, at 64 and 256 spp. A reference (~1024 spp) only for bias.
- **Bit-identical items:** TILEPATHOCL, fixed seed, `tilepath.sampling.aa.size` 8, no multipass; compare to 1e-7 against the previous build on cornell, luxball-hdr, classroom, kitchen, luxball-hdr-vol, cornell-vol, transparencyball, cornell-invis, the shadow-catcher cornell and luxball-shadowcatcher, plus the OpenCL device.
- **Statistical items:** seed pairs and equal means on the GPU.
- **Speed:** `tests/benchmark/renderbench.py`, old and new builds alternating, rays/s on Windows (±1%); the `[AdvancePaths_MK_RT] VGPRs / scratch` log line before and after. Per kernel: `tests/benchmark/kerneltiming.py` (`LUXRAYS_HIP_KERNEL_TIMING=1`); the G0 Blender classroom as a pyluxcore scene: `tests/benchmark/g0_export.py` (`--flat-textures` for the textures' share).

## 3. Tracks

### T1. GPU time per sample (PATHOCL)

Tiers A-C of the speedup plan plus the structural leftovers of the plan. Today: one `AdvancePaths_MK_RT` kernel per iteration, 256 VGPRs, ~2.5 KB scratch, 4 waves per SIMD; it is 86-99% of the GPU time, the HIPRT trace the rest (S0, 2026-10-21). On the G0 Blender classroom the image maps are 20% of the time per sample (31% of an iteration), and even without them a sample costs 5x the repo classroom's. Where a vertex spends its time: three interpreter walks per hit (volumes and pass-through), each texture evaluated 2-3 times per vertex, software bilinear image lookups, a 128-byte `Transform` copy per hit, N+1 wavefront iterations for a path of N vertices, repeated triangle-light work. *History:* SPEEDUP_CHANGES.md "Key facts".

- **A1. Evaluate each texture once per vertex.** A private per-vertex cache (8-16 entries of texture index and float3), cleared at each vertex, consulted by `Texture_GetFloatValue/GetSpectrumValue`; image maps first. If it pays, a material parameter record filled once per hit and shared by Evaluate, Sample and Albedo (Cycles' closure model; the CPU twin is C6). Bit-identical. `include/slg/textures/texture_funcs.cl`, `texture_imagemap_funcs.cl`, `pathoclbase_kernels_micro.cl`, the `TEXTURES_PARAM` macros.
- **A2. Hardware texture objects on HIP and CUDA.** `hipCreateTextureObject` / `cuTexObjectCreate`, a per-page handle buffer referenced from the `ImageMap` descriptor, `tex2D` in `ImageMap_GetSpectrum/GetFloat/GetDuv`; software path kept for OpenCL and the CPU; new hipew/cuew entries. Last-bit differences (hardware 8-bit filter weights), so the test tolerance applies; +33% memory for RGB byte maps. Prerequisite of X1. `src/luxrays/devices/hipdevice.cpp`, `cudadevice.cpp`, `deps/hipew`, `deps/cuew`, `compileimagemaps.cpp`, `imagemap_funcs.cl`, `imagemap_types.cl`.
- **A4. No-stack fast path for one-op materials.** When `evalOpLength == 1`, `Material_Evaluate/Sample/Albedo` call the material function directly with register arguments; Mix and the other multi-op materials keep the interpreter. Bit-identical. Measure on cornell and the Blender classroom.
- **A5. Common subexpression sharing in the texture op compiler.** Memoize per texture index inside one evaluation (a slot area at the bottom of the texture stack, a `COPY_SLOT` op); `compiletextures.cpp:333+` flattens the graph with no sharing, the Blender classroom compiles to 7164 ops. Also shrinks the stacks (helps G11b). After A1 shows the texture share.
- **B1. HitPoint diet** `[PARTIAL]`. Done: the cut-down hit point of the triangle light (a constant emission without an image map reads only the geometry normal and the side) and `Material_GetEmittedRadiance()` without the interpreter for the leaf materials. Left: mesh index and `Transform` read on demand (instanced and motion meshes only; the local texture mappings read the `Transform`, so it needs a mesh-index accessor there); lazy `dndu/dndv` (only generic procedural bump reads them); indices, normals and UVs read once in `HitPoint_Init`. Private BSDF ~352 B → ~200 B. Bit-identical. `hitpoint_types.cl`, `hitpoint_funcs.cl`, `exttrianglemesh_funcs.cl:348-376`, `bsdf_funcs.cl`, `light_funcs.cl`.
- **B2. No extra iteration at the end of a path.** At the last vertex, sample the next camera ray in the same kernel and trace it with the last shadow ray; the finished sample's pending direct-light contribution waits in a small record (pixel, radiance groups, the AOV members with a channel) that the shadow result completes. Same for the Russian-roulette end (`MK_RT_DL_SPLAT`). `DrainPaths` must wait for the pending records. The contribution order changes, so the check is statistical (seed pairs and means on cornell, kitchen, luxball-hdr-vol, the shadow-catcher scene; the drain on the subsurface scene). `pathoclbase_kernels_micro.cl:1029-1035, 1092-1228`, `pathoclbase_datatypes.cl`, `pathoclbaseoclthreadinit.cpp`.
- **B5. Triangle light sampling without repeats.** Vertices from the tree leaf, the solid angle computed once per sample, the pick returning the slot probabilities for the MIS pdf at the next vertex (`DirectHitFiniteLight`). Bit-identical up to float order. `light_funcs.cl:484-601`, `lighttree_funcs.cl:540-617`.
- **C. Occupancy re-assessment** (after A and B). Re-run the `LUXRAYS_HIP_WAVES_PER_EU` sweep and the `-Rpass-analysis=kernel-resource-usage` dump (`hiprtc_remarks.py`). If the kernel then fits 5-6 waves without spilling, the gain is free. If not, the route left is the per-member SoA accessor refactor plus per-state kernels with queues: the old G6 (compaction), the G7 leftover and "material sorting" are this one item (Cycles' own tracker: compaction "not clearly a win" with few kernels per bounce). Multi-week; weigh it then, not now. *History:* PLAN G6, G7 ("rejected" paragraphs), G8 table.
- **G11b. Peak-depth bound of the material evaluation stack** `[PARTIAL]`. Done: the textures (peak depth of the op tree; the G0 Blender classroom 212 -> 21 floats, under the private 32). Left: the materials, sized by the sum of their ops (348 floats on the G0 classroom, 713 MB of shared stacks at 960x540). A peak bound needs the pops and pushes of every material op type (the ops pop their parameters; the sub-node model of the textures gives the sum again). A Mix of two leaf materials peaks at 34 floats and each nesting level adds about 28, so no Mix scene fits the private material stack (16): the gain is the shared buffer (taskCount x bound) and, with a private bound of 64-128 floats measured against the scratch it costs, the private variant for shallow Mix scenes, which also removes the recompile of a viewport Mix edit (1.7-3.1 s against the 15-70 ms kernel load). The addon should also call `RemoveUnusedMaterials()` so an edit back returns to the private variant. *History:* PLAN G11 "Left open" and G11b, G9 step 7.
- *Not pursued:* fused trace and shader execution reordering (OptiX-only, after the state shrink), per-scene kernel specialization (G4, measured and rejected), a private copy of the whole task state (G7, rejected).

### T2. Time to a clean image and the Blender experience

- **O1. GPU OIDN** `[BLOCKED]` on LuxCoreDeps. Add the OIDN CUDA/HIP/SYCL device modules (deps build ships only the CPU one) and take OIDN 2.5.1 in the same rebuild (with K3). `intel_oidn.cpp:171` creates a CPU device and passes host pointers to `newBuffer()`: import the film's device buffer instead. Prefilter none/fast/accurate as Cycles. Retire BCD once `high` runs on the GPU. The OptiX 8/9 denoiser cannot be tested here (no NVIDIA GPU). *History:* PLAN Phase 1 "GPU OIDN 2.x", F2.
- **O2. The per-pixel adaptive halt as the default** `[OPTION]`. `batch.haltthreshold.halfbuffer.enable` (Cycles model) is as fast as or faster than the classic test at equal quality, except at the loosest thresholds; `passes = 2` is the bounded classic fallback. The threshold changes meaning (error of the linear radiance, ~2.2x the tonemapped one), so the default needs new suite references (rendered now at the classic 0.075), the BlendLuxCore threshold UI and defaults, and docs. Refinements: weight the allocation by per-pixel cost; a GPU-side test to remove the ~1 s first-test lag. *History:* PLAN Phase 1 "Cycles-style adaptive sampling", steps 1-2.
- **O3. A halt on the denoised image**, after O1 and O2. Firmino et al. 2024 per-pixel error of the denoised image as the stop criterion (Firmino 2023 needs a derivative OIDN does not expose; Denisova & Bocchi 2024 is the black-box alternative).
- **G9b. Precompiled HIP kernels: the platforms left.** Linux with the ROCm runtime and no SDK; the minimum Adrenalin and ROCm versions that load code object v6 and the generic targets (measure, document, and name it in the addon's message, which names none); macOS (no wheels for now, `5603ff325`); the clang-vs-hiprtc defaults image diff. None can be done on the Windows machine. *History:* PLAN G9 step 7 and "Risks".
- **E1. Scene edits without a full rebuild.** A transform edit rebuilds the whole `DataSet`, the HIPRT scene at high quality on every device and the Embree BVH. Keep the HIPRT geometries across transform edits and rebuild only the instance scene (`hiprtaccelhw.cpp:113-143`, `scenepreprocess.cpp:43-64`); the `Balanced` build for RTPATHOCL; no Embree build when `opencl.native.threads.count = 0`. Then put timers on the rest of the startup (scene compile, synchronous pageable uploads, light tree build, image map upload) and make the uploads asynchronous from pinned memory. Target: the 0.85-4.3 s fixed cost.
- **E4b. Viewport upscale.** An FSR-style upscale of the viewport at Pixel Size > 1, in the image shader of `draw/viewport.py` (BlendLuxCore); the Nearest/Linear filter itself is fixed (BlendLuxCore `72bf7ada`).

### T3. Noise per sample: sampling and light transport

- **D1. Find the Cornell direct-light gap** `[MEASURE]`, one day. The Blender Cornell box without the glass and metal spheres, direct light only in both engines, seed pairs at 64 spp, per-pixel var·spp on the walls (the earlier 8-14x figure was 77% light seen through the glass sphere, a path-depth difference, not sampling). If a gap remains, bisect: the light point from two Sobol dimensions instead of one split by even and odd bits (`sphericaltriangle_funcs.cl`); one quad against two triangles (the tree's 50/50 cut); the MIS weights (BSDF-only and light-only renders). The file is Rec.2020 and the G0 renders before 2026-10-15 ran in Rec.709, so the 0.82x brightness ratio and the 2.2x noise figure are to be re-measured. Decides whether a sampler item follows. *History:* PLAN G0 and light tree step 3.
- **LT. Light tree follow-ups.** (a) Visibility: the sun behind the classroom's blinds still takes 31% of the picks and reaches 8% of them: cap the distant group's share, or a visibility term from DLS-cache-style per-cell cuts of the tree. (b) Pick by the second moment, not the mean contribution. (c) The 16-slot bound of the learning (private arrays). (d) The GPU learns per device, no merge. (e) RTPATHOCL renders with the geometric tree, no epochs. (f) Later: Tokuyoshi et al. 2024 spherical-Gaussian importance for glossy highlights. The 256-triangle AUTO cutoff (BUGS.md "Direct light sampling is off for emissive meshes above 256 triangles") stays until (a) handles decorative lamp meshes. *History:* PLAN Phase 2 light tree, steps 3-4 "Not solved".
- **V1-V4. Cheap volume items** (done). Done: V1 stratified pass-through (cornell-vol -41% variance, cornell-glass -30%); V2 transmittance for shadow rays (with a Russian roulette below 0.1; -4 to -12% variance on the volume scenes, but PATHOCL luxball-hdr-vol -11% samples/s from the shadow rays that now cross the smoke's shell, which V6/V7 remove); V3 spectral MIS in the distance sampling (luxball-hdr-vol -31% variance and -27% time on PATHOCL, bigmonkey-vol -45%). V3b the volume's scatter decision decorrelated from the surface's pass-through choice (the glass furnace with a white medium inside, 0.63 -> 1.00). V4 the null-shell boundary init on the GPU (+4.3% rays/s on luxball-hdr-vol). *History:* PLAN Phase 2 "Volumes and dielectrics: the cheap items".
- **V5-V7. Structural volume items**, 1-2 weeks each. V5 per-segment direct lighting with equiangular sampling and MIS against distance sampling (homogeneous first; V8 needs it). V6 shadow rays that record up to N hits (Embree filter, HIPRT any-hit list), which re-enables the G1 any-hit path on scenes with volumes or transparency. V7 an in-kernel pass-through loop for path rays (profile the boundary-only iterations with `kerneltiming.py` first).
- **V8. Null-scattering tracking, majorant grids, NanoVDB.** Delta tracking for distances, ratio tracking for transmittance, a super-voxel majorant grid walked with DDA, spectral tracking; NanoVDB on the GPU (headers are in the OpenVDB 12.1.1 of the deps); volume emission by next-event estimation; then `multiscattering` on by default and the biased marcher as an option. Needs a heterogeneous density-grid bench scene (none exists) plus `cornell-vol-caustic` and `bigmonkey-vol` in the seed-pair runs. After V5.
- **L1-L3. Cheap light-tracing items** (done). Done: L1 no camera connection where it cannot be caustic and the light path ends at its first non-specular vertex, L2 caustic-only Metropolis importance (causticcube hybrid: -83% variance of the whole image, -60% at the median pixel, +18% time per sample). L3 (filter importance sampling for the splats) dropped: the 3x3 splat costs nothing measurable on LIGHTCPU and halves the per-pixel variance. *History:* PLAN Phase 2 "Light tracing efficiency".
- **L4-L6.** L4 guided emission (a per-light 2D distribution learned from accepted caustic connections; PhotonGI's caustic pass would share it). L5 a lighter eye-side policy. L6 light paths in the PATHOCL kernels as a second task type (what makes light tracing usable on the GPU; L1 and L2 pay twice there). The caustics seen through a specular surface (BUGS.md) stay missing; MNEE covers part of it.
- **M1. Manifold next-event estimation for shadow caustics.** Hanika 2015, as Cycles 3.1: a Newton walk through 1-4 refractive interfaces, opt-in per light, caster and receiver; no cache, so it works in the wavefront. The cost is GPU register pressure: after T1 Tier C.
- **PG. Path guiding.** OpenPGL on the CPU engines (collect, train between passes, guided BSDF sampling with MIS, guided Russian roulette). Risk: Intel discontinued OpenPGL in 2025-08, the ASWF took it over in 2026-04, v0.7.1 is the last release, so expect a fork. GPU guiding is in-house later (a PPG spatial tree of directional quadtrees trained on the CPU from GPU samples).
- **P5. Portal environment light.** pbrt-v4 `PortalImageInfiniteLight`: `scene.lights.<name>.portal = 4 points`, several portals picked by projected solid angle, exact pdf, no cache. After V5 and MC. Addon: export Cycles portal lights as the world light's portal (`export/light.py:121` drops them today). Measure on the kitchen window and an HDRI interior, both devices.
- **MC. MIS compensation and solid-angle sampling defaults** `[OPTION]`. Both are in and off by default. MIS compensation showed no measured gain on luxball-hdr and the sky2 scene; revisit on a sharp HDRI interior once the DLS cache and ELVC estimate the environment's importance consistently with the compensated pdf (a cell lit only by the dim part would estimate zero and drop the light). Solid-angle sampling (`lightstrategy.trianglelight.solidangle`) is waiting for D1 to show whether it pays with the tree.
- **BN. Blue-noise leftovers.** TILEPATHSAMPLER (its own per-tile sequences); the RMSE after OIDN at 1-16 spp (kernel-predicting denoisers are trained on white noise). Small.
- **GM. GPU Metropolis, short chains.** A global luminance estimate (a reduction over the tasks) and a resampled start (PSSMLT bootstrap). Fixes BUGS.md "GPU Metropolis sampler bias with short chains".
- **HW. One wavelength per path.** A sampler dimension kept in the path state of every engine, handed to the materials through the hit point and applied once at the first dispersive vertex. Fixes BUGS.md "Dispersion draws one wavelength per vertex". Hero-wavelength spectral rendering stays optional and long-term (`SWCSpectrum` exists for thin film).
- *Settled, not listed:* ReSTIR (out), throughput Russian roulette (P2, stays an option), path regularization (P3, done, opt-in).

### T4. Materials

- **RG. Rough glass adjoint on light paths.** BiDir and the hybrid light tracing read 2-4% low on rough glass and OpenPBR glass (BUGS.md "BiDir reads 2-4% low on rough glass"): write the adjoint BSDF down explicitly, check it with the slab test, derive the `fromLight` `Sample()` against it. Do it before K1 reaches the materials: that migration's safety net is a render diff, which only proves the code moved unchanged. The BiDir Russian-roulette factor inconsistency (BUGS.md) goes in the same pass.
- **SS. Subsurface deferred items.** The refractive entry of Cycles' skin mode; a local-intersection query for the walk (Embree argument filter, HIPRT filter) instead of tracing through other objects; a configurable step cap (0.934 at radius 0.01, albedo near 1); the walk on light paths (BiDir); the PATHOCL halt bias with walks in flight (BUGS.md "PATHOCL halt bias with the subsurface material"). *History:* PLAN material standards pass, step 9 "Deferred".
- **OP. OpenPBR follow-ups.** Belcour & Barla 2017 thin film with the conductor phase shift (BUGS.md "OpenPBR thin film differs from Cycles"); the subsurface exit through the rough dielectric as Cycles (BUGS.md "OpenPBR subsurface is up to 10% brighter than Cycles"); addon mapping of Coat Normal, Tangent and Subsurface IOR; validation against Adobe's `openpbr-bsdf` and Blender's cross-renderer test suite; Blender 5.4's OpenPBR node mapped one to one when it ships; MaterialX 1.39.5 import as a translation to the `openpbr` node.
- **P4. Stochastic layered BSDF.** pbrt-v4 `LayeredBxDF` / Guo et al. 2018 as `layering = analytic | stochastic` on glossycoating and the OpenPBR coat; checked with the furnace and a geometric thin-shell reference at 1024 spp; on the GPU a loop in the material eval, within the stack budget. Addon: the layering mode on the node.
- **ME. Cloth energy.** Carpaint and the cloth diffuse pass the furnace (re-measured 2026-10-21); the cloth specular (Irawan) lobe is 0.73 head-on and up to 1.32 at grazing (BUGS.md "Cloth (Irawan) gains energy at grazing angles"): a per-preset table of the directional albedo, applied as the energy compensation of the microfacet materials, would make it conserving. A day.
- **HA. Hair.** Chiang et al. 2016 BSDF (pbrt-v4 `HairBxDF`, MaterialX `chiang_hair_bsdf`); native curves on the CPU with Embree 4.4. HIPRT 3.1 has no curve primitive (tessellated ribbons, or an AABB list with a custom intersector as Cycles does): decide ribbons everywhere (parity) or curves on the CPU only.

### T5. Architecture: single-source kernels, build, safety, XPU

- **K1. Single-source kernels** `[PARTIAL]`. Done: the 10 Blender textures and the Blender noise library. - **K4. Safety in C++** `[PARTIAL]`. ASan/UBSan work locally (`LUX_SANITIZE`) but are not in CI; a LuxCore-only ASan run is also the next step on the render-thread segfault (BUGS.md). TSan, clang-tidy and fuzzing of the scene parsers: not started. Cheap, so early.
- **X. XPU (CPU and GPU on one image).** After K1: the same integrator and shading code on both devices, so averaging cannot bias. The scheduling model (a full-frame film per device, lazy merge, the 1% transfer budget) already exists. *History:* PLAN Phase 4.

### T6. Features and interop

- **F1. Ray-cone texture LOD, stochastic filtering, UDIM.** One cone width per path (Akenine-Möller et al. 2021) selects the mip level per lookup; the level is sampled stochastically with one texel fetch (Pharr et al. 2024); one float of path state, the same code on CPU and GPU; fixes the load-time single-level choice at `imagemap.cpp:918`. UDIM tokens in the loader on top. After A2. Measure equal-spp RMSE and samples/s on a scene with large `.tx` textures.
- **F2. Out-of-core texture streaming.** OIIO `TextureSystem`, CPU only (no open-source path tracer streams textures on the GPU). After F1.
- **F3. Lights.** Light linking and shadow linking; the Prague/Nishita sky.
- **F4. Geometry.** Deformation (vertex) motion blur; point clouds.
- **F5. USD Hydra render delegate.** The Hydra 2.0 scene-index API (default since OpenUSD 25.11; scene delegates are deprecated at runtime from 26.03), hdCycles as the template; Alembic and USD geometry come through the USD library. The biggest adoption lever (Houdini, Maya, Blender, Omniverse).
- **F6. Backends.** Metal (MetalRT; macOS is OpenCL-only today, `43654b5c0`) and SYCL/Level Zero with Embree GPU for Intel. Slang is not an option (no HIP target).

### T7. CPU engine (after T1 and T2: it is not where the gap to Cycles is)

- **C6. Per-BSDF parameter cache** shared by Evaluate, Sample and Pdf (Disney reads 11-14 textures per call): the CPU twin of A1's second step. The other small CPU items are in PLAN Phase 1b "Verified findings".
- **C7. CPU/GPU variance parity** `[MEASURE]`. PATHCPU's per-sample tonemapped variance was ~20% above PATHOCL's on cornell 640x480 (16 and 32 independent 32 spp renders, 2026-10-14). The sampler layout changed since: re-measure first, then find the cause.
